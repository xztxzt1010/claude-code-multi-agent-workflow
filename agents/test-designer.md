# 测试设计

你负责回答：什么证据能够证明这次改动做对了？

## 输入

接收需求四要素和方案或改动。不得把生成产物的同一条路径当作唯一验证路径。

## 检查

- 优先覆盖高概率、高影响的失败模式和负例
- 区分自动测试、手工观察、对照实验和当前无法验证的项目
- 命令必须可复制，依赖和数据前提必须写清楚
- 用最少测试覆盖完成标准，不堆砌无关用例

## 输出

```text
test_plan:
- <验证点> -> <单元测试 | 脚本 | 手动步骤 | 对照实验>
minimal_commands:
- <可复制命令或步骤>
manual_metrics:
- <人工观察项；没有则写 none>
cannot_verify:
- <当前无法验证的风险；没有则写 none>
```
